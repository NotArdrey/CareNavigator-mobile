# Rollout monitoring

Run `node tool/monitor_workflows.mjs` after deployment and during the next daily-summary cycles. Its output is aggregate-only and its timestamped local evidence stays ignored. Alert on any request/consultation or confirmed-time mismatch, active terminal grant, duplicate daily summary, missing activation identity or duplicate patient profile. Review failed outbox jobs individually through an authorized super-admin operation, recheck preferences, then retry the existing job. Never reissue a clinical prescription to retry delivery.

Inspect Supabase Auth and Edge logs for 401/403 responses, activation errors, provider failures and dispatcher producer errors. Compare these with the `security_logs` failure count and function versions; Edge authorization rejections can occur before an application security-log insert. Retained RPCs enforce caller identity, role and relationship inside their transaction. The public slot/hospital eligibility RPCs intentionally reveal only directory availability.

The security advisor reports intentionally public availability RPCs, authenticated transactional RPCs and anonymous sign-in policies. These are not a clean-advisor claim: ownership predicates, verified email checks for privileged actions, function ACLs and direct-RLS acceptance checks remain necessary. `appointment_reminder_jobs` intentionally has RLS and no client policy; only the server dispatcher accesses it. Existing `pg_net` extension placement and leaked-password-protection configuration remain deployment notices for operator review. Remediation guidance: https://supabase.com/docs/guides/database/database-linter

The five-minute Cron job uses a Vault dispatcher token. Keep it active while resolving email configuration; jobs show delivery failures truthfully. Revoke the exposed Gmail app password at its owner account, then configure a replacement and a controlled test recipient before retrying email. Do not leave synthetic test-recipient jobs eligible when SMTP is re-enabled.

Before correcting inconsistent live data, export the specific affected identifiers and expected reservation/clinical provenance. Run bounded corrections in a transaction and retain an audit note. Initial aggregate reconciliation found no inconsistent legacy requests, stale confirmations, active terminal grants or duplicate patient profiles. No legitimate appointment or clinical record needed deletion or recreation.
